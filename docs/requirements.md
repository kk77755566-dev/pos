# ガールズバーPOS 要件・実装仕様

## 1. 確定ルール
- 初期は1店舗で運用し、全業務テーブルに store_id を持たせて複数店舗に拡張可能にする。
- 基本セット・延長料金は店舗単位で自由登録する。
- 商品ごとに標準バック率を設定する。
- 商品バックの付与先は注文時に商品明細ごとに選択する。1明細を複数キャストに分配でき、配分率合計は100%以下。残りは店舗取り分。
- 給与は時給＋バック。
- 勤務時間は15分単位。初期値は15分未満切り捨てを候補とするが、給与規則・法令確認後に店舗設定として確定する。
- 税・サービス料・内税外税・計算対象・端数処理は店舗ごとに設定する。
- 日締めは自動集計後、自動確定する。ただし整合性エラーがある場合はblockedとして保留し、推測補完しない。

## 2. データ整合性
- 金額・商品名・バック率・時給・税率・サービス料率は取引確定時のスナップショットを保存する。
- 注文・会計・給与・締めは物理削除しない。取消・反対仕訳・差額調整で履歴を保持する。
- すべての書き込みAPIに冪等性キーを要求し、再送による二重登録を防ぐ。
- APIは認証ユーザーの店舗ID・権限をサーバー側で検証する。
- 締めは store_id + business_date で一意。ロックとトランザクションで二重実行を防止する。
- 締め後の訂正は元締めを上書きせず、調整履歴を残す。

## 3. 日締め自動確定条件
1. 対象営業日の営業中セッション・未会計卓がない。
2. 支払合計と会計確定額が一致する。
3. 注文のdraft状態・処理中状態が残っていない。
4. 取消処理が完了し、バック付与が取消済みである。
5. 出勤中のキャストがいない（退勤漏れを自動補完しない）。
6. 給与と商品バック集計が完了している。
7. 売上内訳・支払方法別内訳に不一致がない。
8. 既に同一店舗・同一営業日の締めが確定していない。

エラー時は closing_errors に理由を保存し、daily_closings.status='blocked' とする。解消後に再集計する。

## 4. 画面一覧
### iPad POS
- 卓一覧：空席、営業中、会計待ち、利用停止。
- 卓詳細：来店人数、セット、延長、担当キャスト、注文履歴。
- 注文：カテゴリ・商品・数量、商品明細ごとのバック率と付与先。
- 会計：セット・延長・商品・割引・税・サービス料・支払内訳。
### スマホ
- スタッフ：注文入力・卓確認（権限による）。
- キャスト：出勤・退勤、当日勤務、自己バック、給与明細。
### PC管理
- ダッシュボード、売上、商品・セット設定、キャスト・時給設定、給与、日締め、経費、店舗設定、監査ログ。

## 6. 計算ルール
### 商品バック
- percentage: unit_price_snapshot × quantity × back_rate_snapshot / 100
- fixed_per_unit: fixed back amount × quantity
- none: 0
- 配分バック額合計は明細バック総額を超えない。端数は最大剰余法等の決定的な配分方法で割り振る。
### 時給
- 実勤務分 = 退勤 - 出勤 - 休憩分
- 15分単位への丸めは店舗設定に従う。丸め方式は floor / half_up / ceil。
- 時給給与 = hourly_wage_snapshot × payable_minutes / 60
- 実際の給与計算では最低賃金・深夜割増・時間外割増・休憩等の法令要件を確認する。
### 会計
- セット・延長・商品・割引を集計。
- 税・サービス料の計算順序、対象、内税外税、端数処理を店舗設定から決定。
- 確定時の内訳・設定スナップショットを保存する。
